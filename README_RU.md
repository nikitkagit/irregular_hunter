# irregular_hunter

C++17-инструмент, который генерирует случайные системы уравнений над
множествами натуральных чисел, решает их итеративно и ищет множества,
структура которых **нерегулярна** — то есть которые не выглядят как
«почти периодические» согласно настраиваемой эвристике.

Проект построен поверх
[`conjunctive_unary`](https://github.com/nikitkagit/conjunctive_unary), который
предоставляет дерево выражений, парсер и решатель уравнений.

## Обзор

Для системы вида

```text
V1 = {1, 2, 3} | (V2 & V3)
V2 = (V1 + {1}) & {2, 3, 4}
V3 = {V1, 2} + {3} | {10}
```

`irregular_hunter`:

1. генерирует случайную систему такого вида (число уравнений, глубина,
   распределение операторов, размеры множеств и т.п. настраиваются),
2. парсит её и запускает решатель на заданное число итераций,
3. классифицирует каждое полученное множество как **регулярное**
   (в конце концов периодическое) или **нерегулярное** согласно
   `RegularityCriteria`,
4. повторяет попытки с новым seed'ом, пока не найдёт систему с заданным
   числом нерегулярных переменных (или пока не исчерпает бюджет попыток),
5. записывает текстовый отчёт с системой, решением и вердиктами
   регулярности.

## Возможности

- Генератор случайных систем уравнений с тонкой настройкой: число
  уравнений, глубина выражений, распределение операторов, размеры
  фиксированных множеств, доля forward references и многое другое.
- Пошаговый решатель с настраиваемым лимитом итераций и правилом
  «быстрой сходимости»: если система стабилизируется раньше
  `min_iterations`, все её множества объявляются регулярными.
- Эвристический чекер регулярности с несколькими независимыми
  параметрами:
  - максимально допустимое отношение размера конечного префикса к
    размеру периодического хвоста,
  - максимальный проверяемый период,
  - минимальный размер периодического хвоста,
  - `ignore_below` — отбрасывание «шумных» маленьких значений,
  - `tail_percent` — пропуск непроверяемого хвоста у верхней границы,
  - `min_period_additions` — требование настоящего повторения паттерна.
- Командная строка с оверрайдами, которые **мержатся** в JSON-конфиг;
  конфиг тем самым играет роль постоянного состояния.
- Автоматическая генерация случайного seed'а, если эффективный seed
  равен `0`. Сгенерированный seed используется для запуска и попадает
  в имя выходного файла, но `0` в конфиге остаётся нетронутым.

## Требования

- CMake ≥ 3.16
- Компилятор с C++17 (MinGW-w64 g++, GCC, Clang или MSVC)
- [`nlohmann/json`](https://github.com/nlohmann/json) для разбора конфига
- [`conjunctive_unary`](https://github.com/nikitkagit/conjunctive_unary)
  для деревьев выражений, парсинга и решения

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

Опционально через пресеты:

```bash
cmake --preset default
cmake --build --preset default
```

## Использование

```
irregular_hunter [options]
```

| Опция | Аргумент | По умолчанию | Описание |
|-------|----------|--------------|----------|
| `-s`  | `<S>`    | `0`          | Seed RNG. `0` означает «сгенерировать новый seed для этого запуска». |
| `-n`  | `<N>`    | из конфига   | Максимум итераций на систему. |
| `-i`  | `<N>`    | из конфига   | Минимум итераций, при котором сходимость считается «осмысленной». Если система стабилизировалась раньше, все её множества объявляются регулярными. |
| `-e`  | `<N>`    | из конфига   | Сколько уравнений генерировать. |
| `-d`  | `<N>`    | из конфига   | Максимальная глубина дерева выражения. |
| `-m`  | `<N>`    | из конфига   | Максимальное числовое значение в фиксированных множествах. |
| `-a`  | `<N>`    | из конфига   | Максимальное число попыток генерации. |
| `-k`  | `<N>`    | из конфига   | Требуемое число нерегулярных переменных в принимаемой системе. |
| `-p`  | `<N>`    | из конфига   | Максимальный период, проверяемый на регулярность. |
| `-r`  | `<P>`    | из конфига   | Максимальное отношение конечного префикса к периодическому хвосту, в процентах. |
| `--no-filter` | — | —          | Принять первую же сгенерированную систему, независимо от её регулярности. |
| `-h`, `--help` | — | —         | Показать справку и выйти. |

Если флаг передан в командной строке, его значение записывается обратно
в конфиг. Поля, которые не были переопределены, сохраняются — таким
образом, конфиг накапливает настройки между запусками.

## Файл конфигурации

По умолчанию приложение читает и обновляет `config.json` рядом с
исполняемым файлом (или в текущей рабочей директории). Все
распознаваемые ключи необязательны и при отсутствии подставляются из
встроенных значений по умолчанию `IrregularSystemWriterParameters`.

Пример:

```json
{
  "generator": {
    "seed": 12345,
    "num_equations": 6,
    "max_depth": 3,
    "max_constant_value": 20,
    "min_set_size": 1,
    "max_set_size": 4,
    "internal_node_percent": 60,
    "leaf_variable_percent": 60,
    "leaf_unknown_variable_percent": 20,
    "operator_union_percent": 34,
    "operator_sum_percent": 33,
    "operator_intersection_percent": 33,
    "min_operands": 2,
    "max_operands": 3
  },
  "criteria": {
    "max_finite_to_periodic_percent": 10.0,
    "max_period": 1024,
    "min_periodic_count": 10,
    "ignore_below": 0,
    "tail_percent": 1.0,
    "min_period_additions": 10
  },
  "max_iterations": 100,
  "min_iterations": 30,
  "require_irregular": true,
  "required_irregular_count": 1,
  "max_attempts": 100
}
```

Поведение при `seed = 0`:

- если загруженный seed равен `0` (из конфига или из явного `-s 0`) —
  для этого запуска генерируется новый случайный seed,
- сгенерированный seed используется при построении отчёта и попадает в
  имя выходного файла,
- файл конфигурации на этом шаге **не изменяется**; `0` остаётся в
  конфиге, так что следующий запуск снова возьмёт новый seed.

Запуск:

```bash
irhunter
```

Вывод в консоль:

```
Report written to: irregular_system_seed42_1712345678901.txt
```

Файл отчёта содержит использованный seed, полную систему, значения всех
переменных и вердикт регулярности для каждой переменной.

## Известные ограничения

- **Эвристика, а не теоретико-вычислительное решение.** Чекер
  приближает «в конце концов периодическое». Множество может быть
  отвергнуто из-за маленького `min_periodic_count` или принято из-за
  единственной совпавшей пары на границе. Настраивайте критерии, а не
  полагайтесь на математическое свойство.
- **Маленькие множества.** Множества меньше `min_periodic_count`
  отвергаются, даже если тривиально периодичны; исключения — пустое
  множество и множества, ставшие пустыми после `ignore_below`.
- **`min_iterations` и быстрая сходимость.** Если система стабилизируется
  раньше `min_iterations`, все переменные объявляются регулярными без
  запуска чекера. Это сделано намеренно и может скрыть настоящую
  нерегулярность в очень маленьких системах.
- **Нет резервной копии конфига.** `ConfigUpdater` перезаписывает
  `config.json` «на месте». Держите копию, если файл важен.
